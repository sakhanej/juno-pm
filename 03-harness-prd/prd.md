## Problem & user

RocketShip PMs need this handled: Juno is an AI Associate Product Manager that helps PMs capture feature signals from selected chat sources, turn confirmed requests into traceable Jira intake items, and bring qualified opportunities together for release planning. The PM owns product decisions. In the MVP, Juno syncs only when asked and prepares Jira items for review; it does not create or reprioritize issues independently.. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

juno sees only the sources the PM connects and selects: specified Webex Spaces or supported chat channels, plus relevant Jira issues and release context. Each finding retains its source reference and timestamp. Juno can use Confluence context when connected and relevant. It must distinguish source evidence from its own inference and flag unclear conversations as NEEDS CLARIFICATION.

For the MVP, support Webex first and add other chat clients through connectors as they become available. “Generic chat client” describes the product direction, not an assumption that every client is already integrated.

**How fresh must it be**

With every re-sync, new chat sources could pop up or more evidence is added to existing once. When not reachable , resume with what exist latest

## 02 Tools · System Capabilities

**The verb list**

Chat sources: list selected Spaces or channels, retrieve messages and thread context, and link back to the source.
Jira: search for duplicates and prepare an intake draft. Create an item only when the PM directs it. Change priority only when directed.
Dashboard: show new and previously tracked feature conversations together, with source, summary, status, and Jira link when one exists.
Confluence: read relevant product context when connected. Keep PRD creation out of this MVP unless it is added as a defined task.

**Deliberate omissions**

No posting on Webex Chats to reply.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

A sync starts only when the PM presses Re-sync. Juno checks selected sources since the last successful sync, processes each new conversation once, and deduplicates against tracked items and Jira. Retry transient source failures up to two times; if a source still fails, show it as unsynced and preserve completed results.

For clarification, ask one focused question at a time. If the PM cannot resolve the ambiguity, retain the item as NEEDS CLARIFICATION and stop treating it as ready for Jira.

**Latency and cost target**

Since you are doing a chat sync, take max 2 min to perform the sync and keep track of synced spaces or new chats and when new sync is performed start from where you left

## 04 Memory · Data Requirements

**What persists, at what scope**

Maintain a workspace-scoped feature ledger containing source references, summaries, status, duplicate links, Jira keys, last-sync cursors, and timestamps. Preserve PM corrections that help maintain those records. Retain only the conversation content needed to support the feature record; avoid storing unnecessary personal information or full transcripts. Keep records isolated to the workspace and its access permissions.

**Expiry and write rules**

Once human makes a chat or potential feature as invalid

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Juno may read selected sources after the PM starts a sync, summarize evidence, identify possible duplicates, and prepare internal analysis or Jira drafts. It must wait for explicit direction before creating or changing Jira items, changing priorities, or publishing content. It must not draft or send external customer communications. Route contract, legal, and regulator matters to the PM. Any continuous background monitoring should require a separate opt-in; it is outside the manual-sync MVP.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

Before showing a finding, Juno checks that its source reference resolves, the summary matches the cited conversation, and any Jira match is real. It labels interpretations as inferences and blocks unresolved ambiguity from being presented as fact. Track pilot quality through feature-detection precision and recall, citation accuracy, duplicate rate, PM correction rate, false Jira creations, and time saved in finding and consolidating requests.

**Failure behaviour**

Make the output as unverified and ask user to drop it or consider it
